# 🎒 نظام توزيع الشنط لوجه الله

نظام ويب كامل لإدارة توزيع الشنط الشهرية للمستفيدين: تسجيل بيانات المستفيدين، إصدار كارت شخصي بباركود لكل واحد، وتسليم الشنطة عن طريق مسح الباركود — مع منع الاستلام أكتر من مرة في الشهر تلقائيًا.

## 🧱 التقنيات المستخدمة

- **Next.js 14** (App Router) + **TypeScript**
- **Prisma ORM** + **SQLite** (قاعدة بيانات ملف واحد، مفيش سيرفر خارجي مطلوب)
- **Tailwind CSS** للتصميم (واجهة عربية RTL بالكامل)
- **JsBarcode** لتوليد الباركود (Code128)
- **jose** لجلسات الدخول (JWT في كوكي HttpOnly)
- **Zod** للتحقق من صحة البيانات

## 📋 المتطلبات قبل التشغيل

- Node.js نسخة 18 أو أحدث
- اتصال إنترنت عادي (لتحميل الحزم ومحرك Prisma في أول مرة فقط)

## 🚀 خطوات التشغيل (خطوة بخطوة)

### 1. تثبيت الحزم

```bash
cd bags-app
npm install
```

### 2. إعداد ملف البيئة `.env`

انسخ الملف المثال:

```bash
cp .env.example .env
```

افتح `.env` وعدّل القيم دي **قبل التشغيل الفعلي**:

```env
DATABASE_URL="file:./dev.db"

# غيّر اسم المستخدم وكلمة المرور دول لأي حاجة سرية وقوية
ADMIN_USERNAME="admin"
ADMIN_PASSWORD="ضع-كلمة-مرور-قوية-هنا"

# غيّر ده لنص عشوائي طويل (مثلاً 32+ حرف)
JWT_SECRET="ضع-نص-سري-عشوائي-طويل-هنا"

# اسم الجمعية/المبادرة اللي هيظهر على الكروت والموقع
NEXT_PUBLIC_ORG_NAME="توزيع شنط لوجه الله"
```

> ⚠️ **مهم:** ملف `.env` ده فيه بيانات حساسة، متبعتوش لحد ومتشيله في git (تم استثناؤه بالفعل في `.gitignore`).

### 3. إنشاء قاعدة البيانات

```bash
npx prisma migrate dev --name init
```

الأمر ده هيعمل ملف `prisma/dev.db` تلقائيًا وينشئ الجداول المطلوبة.

### 4. (اختياري) إضافة بيانات تجريبية للتجربة

```bash
npm run seed
```

### 5. تشغيل الموقع

```bash
npm run dev
```

افتح المتصفح على: **http://localhost:3000**

هيوجهك تلقائيًا لصفحة تسجيل الدخول، وادخل بنفس الـ `ADMIN_USERNAME` و`ADMIN_PASSWORD` اللي حطيتهم في `.env`.

## 🖥️ الاستخدام اليومي

### إضافة مستفيد جديد
من `لوحة التحكم → إضافة مستفيد`. بعد الحفظ، هيتحول تلقائيًا لصفحة المستفيد اللي فيها الكارت جاهز للطباعة.

### طباعة الكروت
- كارت واحد: من صفحة المستفيد نفسه، زرار "🖨️ طباعة الكارت"
- كل الكروت مرة واحدة: من `لوحة التحكم → 🖨️ طباعة كل الكروت`

مقاس الكارت مضبوط قريب من مقاس البطاقة الشخصية (85×54مم تقريبًا)، تقدر تقصه بعد الطباعة أو تطبعه على ورق كروت جاهز.

### تسليم شنطة (نقطة التوزيع)
من `لوحة التحكم → تسليم شنطة`:
1. حط أي قارئ باركود USB أو بلوتوث متوصل بالجهاز (بيشتغل زي الكيبورد تمامًا، مفيش إعداد إضافي مطلوب)
2. امسح باركود الكارت — هيتحط الكود في الخانة ويتبعت لوحده تقريبًا (القارئات بترسل Enter في الآخر)
3. لو أول مرة الشهر ده → هيظهر ✅ وبيانات الشخص عشان تتأكد منها قبل ما تدّيه الشنطة فعليًا
4. لو استلم قبل كده الشهر ده → هيظهر ❌ برسالة واضحة ومايتسجلش استلام تاني

النظام بيمنع الاستلام المكرر على مستوى قاعدة البيانات نفسها (مش بس الواجهة)، يعني حتى لو حصل خطأ أو ضغط سريع مرتين، مش هيتسجلش إلا مرة واحدة لكل شهر.

## 🔒 ملاحظات أمان مهمة

- غيّر `ADMIN_PASSWORD` و `JWT_SECRET` قبل أي استخدام حقيقي — القيم في `.env.example` للتجربة فقط.
- الرقم القومي والموبايل بيتخزنوا في قاعدة بيانات محلية (`prisma/dev.db`) — خد نسخة احتياطية دورية من الملف ده.
- الباركود المطبوع على الكارت كود عشوائي مستقل عن الرقم القومي (مش الرقم القومي نفسه)، فلو حد لقط الكارت مايقدرش يوصل لبيانات حساسة منه مباشرة.
- لو هتنشر الموقع على الإنترنت (سيرفر عام)، لازم يكون فيه HTTPS عشان الكوكي بتاع الجلسة يبقى آمن (`secure: true` مفعّل تلقائيًا في وضع production).

## 📡 الاشتغال بدون إنترنت (Offline / PWA)

الموقع مبني كـ **PWA (Progressive Web App)** ومصمم عشان يفضل شغال حتى لو النت اتقطع فجأة في نقطة التوزيع، وبعدين يزامن البيانات تلقائيًا مع السيرفر أول ما النت يرجع.

### إزاي تفعّله على الجهاز

1. افتح الموقع وسجّل دخول **وانت متصل بالإنترنت** (لازم مرة واحدة على الأقل).
2. افتح صفحات "تسليم شنطة" و"المستفيدون" و"إضافة مستفيد" مرة كل واحدة وانت متصل — ده بيخزن الصفحات نفسها (Service Worker) وبيانات كل المستفيدين (IndexedDB) على الجهاز.
3. (اختياري بس مفيد) من المتصفح: "إضافة إلى الشاشة الرئيسية" / "Install App" — عشان يشتغل زي أبليكيشن مستقل من غير ما يفتح المتصفح.

بعد الخطوات دي، لو النت اتقطع فجأة:

| الوظيفة | بيشتغل أوفلاين؟ | التفاصيل |
|---|---|---|
| فتح الصفحات (تسليم شنطة، المستفيدون، إضافة مستفيد) | ✅ | الصفحات متخزنة على الجهاز من أول زيارة أونلاين |
| تسليم شنطة (مسح باركود) | ✅ | بيتحقق من البيانات المحفوظة محليًا، ويسجل التسليم محليًا، ويمنع تكرار الاستلام لنفس الشخص في نفس الشهر على مستوى نفس الجهاز |
| إضافة مستفيد جديد + طباعة كارته | ✅ | بيتسجل محليًا ويظهر تنبيه برتقالي "بانتظار المزامنة"، والكارت والباركود بيتطبعوا عادي فورًا |
| تعديل بيانات مستفيد موجود / حذف مستفيد | ❌ | محتاج إنترنت (نادرًا ما يحصل وانت في نقطة التوزيع) |
| تسجيل دخول لأول مرة | ❌ | لازم إنترنت أول مرة بس |

### إزاي المزامنة بتشتغل

- فيه مؤشر أعلى الصفحة يوضح "متصل 🟢" أو "غير متصل 🟠"، ولو فيه بيانات مستنية المزامنة بيظهر عددها وتقدر تضغط عليه للمزامنة الفورية.
- أول ما النت يرجع، الموقع بيحاول يزامن تلقائيًا كل شوية (كل 20 ثانية لحد ما ينجح).
- لو حصل **تعارض** (مثلاً حد استلم الشنطة من جهازين مختلفين في نفس الوقت وهما أوفلاين، أو حد اتسجل برقم قومي موجود بالفعل)، السجل بيتحول لحالة "⚠️ تعارض" وبيفضل ظاهر في قائمة الانتظار عشان تراجعه يدويًا — مش بيتحذف لوحده.
- لو مستفيد اتضاف أوفلاين وطبعت كارته، وبعدين حصل تعارض نادر في الباركود وقت المزامنة، هيظهر تنبيه إنك لازم تعيد طباعة الكارت.

### حدود مهمة تعرفها

- الأوفلاين ده حماية من **انقطاع مؤقت للنت في نفس الجهاز**، مش بديل عن قاعدة بيانات موزعة. لو بتشغل الموقع من كذا جهاز في نفس الوقت وكلهم أوفلاين سوا، ممكن يحصل تعارض بسيط (مثلاً نفس الشخص ياخد الشنطة من جهازين مختلفين بغلط) — والنظام بيكشف ده وقت المزامنة ويوريك تنبيه، بس مايقدرش يمنعه فعليًا وهو حصل أوفلاين.
- خلي بالك: الكاش المحلي (بيانات المستفيدين) بيتحدّث كل دقيقتين تلقائيًا وقت الاتصال، فلو حد استلم شنطته من جهاز تاني قبل ما تنقطع النت عندك بلحظات، ممكن الجهاز بتاعك ميكونش لسه اخد آخر تحديث.

## 🌐 النشر أونلاين (على سيرفر حقيقي)

الموقع عادي يشتغل على أي استضافة بتدعم Node.js (VPS عادي، أو منصات زي Railway/Render). لو محتاج قاعدة بيانات أقوى من SQLite لعدد كبير من المستخدمين المتزامنين، ممكن تستبدلها بـ PostgreSQL بسهولة: غيّر `provider` في `prisma/schema.prisma` من `sqlite` لـ `postgresql` وحدّث `DATABASE_URL`.
